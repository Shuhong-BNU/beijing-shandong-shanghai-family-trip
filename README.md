## 项目定位

这是一次真实家庭旅行的路线规划与执行工具。四段航班已经锁定，项目围绕固定航班倒推北京、青岛、威海、上海四地安排，并在山东段保留自驾 / 不自驾、深度 / 轻松等多条可切换路径。

规划目标：**父母体验优先、减少折返与过度疲劳、保留动态调整空间，并严格区分官方事实、规划判断、精确账单与预估参考。**

## 三套独立界面

- **方案速览**：比较 A–E 五套方案并选择当前方案。
- **执行行程**：只显示当前方案；方案总流程可折叠，8 天执行流程显示逐节点日期、城市、距离、时长与内嵌地图。
- **完整研究**：保留天气、景点池、住宿、逐餐、交通、租车、票务、成本、删减、方法与来源。

底部提供 **总览 / 每天 / 预订 / 研究** 四个快捷入口。

## 五套正式方案

- **A｜主推**：北京 1 / 青岛 2 / 威海 2 / 上海 2；青岛不租车，8 月 24 日威海单日自驾。
- **B｜零驾驶**：山东段以铁路 / 地铁 / 网约车为主。
- **C｜青岛深度**：青岛 3 晚 + 威海 1 晚，重点加入崂山。
- **D｜山东跨城自驾**：青岛取车，经荣成 / 威海活动，威海机场还车。
- **E｜慢节奏减负**：每天一个主项目 + 一个轻量散步或休息模块。

## v1.3.0 路线数据架构

### 1. 60 个唯一转场已一次性冻结

`AMAP_WEB_SERVICE_KEY` 只保存在 GitHub Actions Secret 中，不进入公开仓库。GitHub Actions 已实际验证该 Key，并把 A–E 五方案中去重后的 **60 个唯一转场全部冻结成功，failures = 0**。

正式数据文件：

```text
assets/data/route-metrics-v131.json
```

其中保存：

- 起点 / 终点；
- 交通方式；
- 实际道路 / 步行 / 公交路线距离；
- 高德预计时长；
- 冻结时的路线 polyline（GCJ-02）；
- 数据来源与生成时间。

因此访客打开网页时**不再调用高德 Web Service 做实时路径规划**，避免重复请求、时延和同一版本下结果漂移。

### 2. 各交通方式口径

- **飞机**：机场间大圆直线距离；已知航段使用计划飞行时长。
- **驾车 / 网约车**：高德 Web Service 实际道路距离 + 预计时长，开发阶段冻结。
- **步行**：高德实际步行路线距离 + 时间，开发阶段冻结。
- **地铁 / 公交**：高德综合公交规划，开发阶段冻结。
- **铁路**：高德综合交通结果只用于辅助路线长度；**具体列车时间最终以 12306 实际选定车次为准**。
- **上海虹桥 → 浦东**：高德路线长度可作空间参考，但时间继续采用机场联络线官方约 40 分钟口径。
- **刘公岛轮船**：水上段显示直线水距和本行程执行预留，不冒充官方纯航行里程。

### 3. Web端（JS API）只负责“画地图”

下一层只需要高德 **Web端（JS API）Key** 来加载高德底图：

```text
冻结 JSON
   ↓
浏览器直接读取 distance / duration / polyline
   ↓
高德 JS API
   ↓
显示底图 + 编号 Marker + 已冻结路线
```

也就是说，JS API 开启后也不会重新计算 60 段路线。

## 高德 Key 安全原则

### Web Service Key

- GitHub Secret 名：`AMAP_WEB_SERVICE_KEY`；
- 仅路线变化、需要重新冻结时使用；
- 不发送给浏览器；
- 不提交到公开仓库。

仓库保留一个手动工作流：

```text
.github/workflows/freeze-amap-routes.yml
```

以后路线有变化时手动运行即可重新生成冻结 JSON。

### Web端（JS API）Key

- JS Key 本身必然会发送到浏览器，不能视为真正的 Secret；
- 应在高德控制台限制到 `shuhong-bnu.github.io` 域名；
- `securityJsCode` 正式部署更推荐放服务端代理，由页面配置 `serviceHost`，不要直接写进公开仓库；
- 测试阶段可先保存在当前浏览器 localStorage 验证地图。

## 每日地图表现

- A–E 五方案每天都有独立路线视图；
- 地图直接嵌在页面内，不要求跳到地图 App；
- 地图只显示编号 Marker 与冻结路线，不把长标签叠在图上；
- 飞机 / 铁路跨城日拆成“出发地本地路线 → 长途转场卡 → 到达地本地路线”；
- 即使没有配置 JS API Key，冻结后的距离 / 时长、执行流程和节点表仍然可直接使用。

## 景点与图片

- 景点池保留 100 分评分、全部景点总表、四城分表、优先级、通用评价与本次旅行判断。
- 当前图片层仍在继续优化；最终目标是优先采用中国大陆可稳定加载的本地化授权缩略图，避免把境外图片热链作为唯一展示方式。

## 票务与成本

- 抢票清单保留官网 / App / 微信小程序 / 售卖时间口径。
- 五方案同时保留“不含大交通的预估参考”和“精确成本计算器”。
- 酒店、租车、网约车、餐饮、铁路等动态商品以真实支付页 / 订单 / 菜单为准。
- 精确成本输入保存在当前浏览器 localStorage。

## 景点评分原则

100 分模型属于项目规划层判断：

- 代表性 / 城市地位：25
- 首次到访价值：20
- 带父母友好度：20
- 本次路线适配度：20
- 暑期体验质量：10
- 执行难度 / 成本友好度：5

评分用于横向决策，不冒充官方评级。
