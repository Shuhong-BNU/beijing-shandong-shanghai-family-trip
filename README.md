## 项目定位

这是一次真实家庭旅行的路线规划与执行工具。四段航班已经锁定，项目围绕固定航班倒推北京、青岛、威海、上海四地安排，并在山东段保留自驾 / 不自驾、深度 / 轻松等多条可切换路径。

规划目标：**父母体验优先、减少折返与过度疲劳、保留动态调整空间，并严格区分官方事实、规划判断、精确账单与预估参考。**

## 三套独立界面

- **方案速览**：比较 A–E 五套方案；v1.3.3 为每个方案增加可折叠的高德全程总路线图。
- **执行行程**：只显示当前方案；顶部有当前方案全程总路线图，下方继续保留 8 天逐日执行流程与每天局部地图。
- **完整研究**：保留天气、景点池、住宿、逐餐、交通、租车、票务、成本、删减、方法与来源。

底部提供 **总览 / 每天 / 预订 / 研究** 四个快捷入口。

## 五套正式方案

- **A｜主推**：北京 1 / 青岛 2 / 威海 2 / 上海 2；青岛不租车，8 月 24 日威海单日自驾。
- **B｜零驾驶**：山东段以铁路 / 地铁 / 网约车为主。
- **C｜青岛深度**：青岛 3 晚 + 威海 1 晚，重点加入崂山。
- **D｜山东跨城自驾**：青岛取车，经荣成 / 威海活动，威海机场还车。
- **E｜慢节奏减负**：每天一个主项目 + 一个轻量散步或休息模块。

## v1.3.3 重点优化

### 1. A–E 五方案全程高德总路线图

- “方案速览”新增五张独立总路线图，A / B / C / D / E 各一张。
- 每张总图都是独立 `<details>` 折叠块，默认不创建 AMap；用户展开后才加载高德底图、Marker、路线与标签。
- “执行行程”顶部同时显示当前选中方案的同款总路线图，形成 **全局总图 + 每日局部图** 两层阅读结构。
- 总图聚合该方案 8 天全部地理节点；重复到访同一地点会合并到一个地理 Marker，但详标会并列显示全部 Day / 日期，不丢失到访信息。
- Day 8 显式补齐双分支：爸妈 `虹桥 → 赣州`，女友 `虹桥 → 浦东 → 广州`。

### 2. 总图节点详标

- 每个地理节点都有唯一编号 Marker。
- 详标直接贴在对应节点旁，内容包含 **Day 几 + 日期 + 节点名称**；重复地点会列出多个 Day / 日期。
- 详标默认显示，可点击“隐藏节点详标 / 显示节点详标”切换。
- 地图在 `zoomchange / moveend / resize` 后重新计算标签偏移；使用多方向、多半径候选位置，尽量避免邻近标签互相压住。
- 全国尺度主要看全局关系；城市内精确位置继续由每天局部地图承担。

### 3. 路线顺序、颜色与方向

- 总图按全程实际段序逐段着色，相邻段使用高对比颜色，不再用一种颜色代表一整类交通方式。
- 每一段都有对应图例：`D几 + 日期 + 段序 / 分支 + 交通方式`。
- 高德 Polyline 使用 `showDir: true` 显示行进方向箭头。
- 飞机、铁路、步行、轮渡等长途 / 特殊段使用虚线；没有冻结 polyline 的航段使用节点间直线表达空间关系。

## 路线数据架构

`AMAP_WEB_SERVICE_KEY` 只保存在 GitHub Actions Secret 中。A–E 五方案去重后的 60 个唯一转场已经冻结到：

```text
assets/data/route-metrics-v131.json
```

v1.3.3 只是聚合和展示这些冻结路线，不重新调用高德 Web Service 算路，也没有重冻路线数据。

## 高德生产架构

```text
GitHub Pages
  ├─ Web端（JS API）Key：浏览器可见 + 高德域名白名单
  ├─ serviceHost
  ↓
Cloudflare Worker
  ├─ AMAP_SECURITY_CODE：Secret
  ↓
高德 JS API
```

- `securityJsCode` 不写入公开仓库，也不发送给访客浏览器。
- 路线 Web Service Key 继续只保存在 GitHub Actions Secret，用于路线变化时重新冻结。

## 景点评分原则

100 分模型属于项目规划层判断：

- 代表性 / 城市地位：25
- 首次到访价值：20
- 带父母友好度：20
- 本次路线适配度：20
- 暑期体验质量：10
- 执行难度 / 成本友好度：5

评分用于横向决策，不冒充官方评级。
